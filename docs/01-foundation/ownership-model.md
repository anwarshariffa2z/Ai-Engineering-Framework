# Ownership Model

Every AI system has named individuals for product outcomes, technical decisions, evaluation integrity, data stewardship, and operations. One person may hold multiple roles in a small team, but accountability must remain explicit.

| Role | Accountable for |
| --- | --- |
| Product owner | Intended use, user outcomes, non-goals, and business acceptance of residual risk. |
| Technical lead | Architecture, integration boundaries, maintainability, and change management. |
| Evaluation owner | Evaluation design, dataset suitability, analysis of results, and quality acceptance. |
| Data steward | Lawful and approved data use, classification, retention, quality, and access. |
| Service owner | Production reliability, observability, incident response, and retirement execution. |
| Risk reviewer | Independent challenge for systems whose risk tier requires it. |

Ownership is recorded in the system’s release evidence and reviewed whenever the system changes materially.
