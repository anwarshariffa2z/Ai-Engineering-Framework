# Framework Glossary

| Term | Definition |
| --- | --- |
| Audit Phase | A bounded stage of evidence inspection with a defined purpose, inputs, outputs, and completion criteria. |
| Playbook | A repeatable, role-oriented procedure for responding to a known operational or governance situation. |
| Evidence | A versioned, attributable artifact that supports a decision, claim, control, or evaluation result. |
| Verification | Confirmation that a declared property, control, or artifact conforms to a stated requirement. |
| Runtime Validation | Verification performed against an executing system or its observable behavior. |
| Repository Health | The measurable integrity, maintainability, discoverability, and policy conformance of a repository. |
| Knowledge Graph | A graph representation of entities, relationships, provenance, and constraints used to reason across connected information. |
| Business Rule | A testable policy or constraint that governs a business decision, workflow, or outcome. |
| Framework Artifact | A maintained document, record, rule, template, checklist, or evidence item governed by this framework. |
| Document Registry | The canonical inventory of framework documents, their metadata, and locations. |
| Audit Engine | A planned deterministic evidence-checking capability; it does not independently approve releases or make risk decisions. |
| Risk Tier | The control level selected from impact, autonomy, data sensitivity, scale, reversibility, and uncertainty. |
| Material Change | A change capable of altering outcomes, risk, data handling, authorization, model behavior, cost, reliability, or compliance posture. |
