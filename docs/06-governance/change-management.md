# Change Management

A change is material when it can alter user outcomes, risk, data handling, authorization, model behavior, cost, reliability, or compliance posture. Material changes require an impact assessment and proportional re-evaluation before release.

Examples include changing a model or provider, prompt or system instruction, retrieval corpus, tool permission, workflow routing, safety policy, data source, user segment, or deployment region. Cosmetic user-interface changes that do not alter the workflow may use normal product review.

Each material change record identifies the reason, affected versions, expected behavior difference, risk impact, evaluation plan, approver, rollout scope, and rollback condition. Emergency changes are documented immediately after stabilization.
